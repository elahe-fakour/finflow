# ADR 0001: Adopt shadcn/ui for Reusable UI Primitives

- Status: Accepted
- Date: 2026-09-20

## Context

FinFlow needs accessible, reusable primitives such as buttons, inputs, cards, and
badges. Building every primitive from scratch would repeat common accessibility and
interaction work, while a black-box component library would limit control over the
portfolio project's UI and code.

FinFlow already has semantic design tokens in `src/app/globals.css`, a `@/*` import
alias, Tailwind CSS 4, and Lucide icons.

## Decision

Adopt shadcn/ui with the `radix-nova` style. Configure it manually rather than
running an automatic initializer so the existing FinFlow design tokens remain the
source of truth.

The configuration uses:

- CSS variables and the existing Tailwind CSS 4 global stylesheet
- Radix primitives for upcoming accessible interactive components
- Lucide as the icon library
- `src/components/ui` as the destination for generated component source
- The `cn` package as the shared class-name utility

## Consequences

Component source generated by shadcn/ui will be committed to this repository. The
team can inspect, adapt, and test it as FinFlow evolves.

Adding a component may install only the dependencies it needs. Components must still
be reviewed for token alignment, accessibility, responsiveness, and unnecessary
animation before use.

The automatic initializer is intentionally not used because it can change global CSS
and utility setup. The manual configuration adds only the required shared imports and
preserves FinFlow's semantic tokens.

## Alternatives Considered

- **Build every primitive from scratch:** maximum control, but repeats established
  accessibility work and slows delivery.
- **Use a black-box library such as MUI or Chakra UI:** faster initial delivery, but
  less source ownership and more visual customization overhead.
- **Use Radix directly:** powerful and accessible, but still requires more styling
  and composition than is needed for this project stage.
